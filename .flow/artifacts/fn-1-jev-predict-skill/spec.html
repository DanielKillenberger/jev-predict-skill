Thesis

scope: business

A /jev-predict-skill that takes any skill as an argument, first asks whether it is predictable by jev, and for /flow-next-flow names the phase the conductor would choose — without running it.

Load-bearing: assessment is a gate. If Jev cannot break the skill into structured outcomes, report that and invent nothing. The flow-next-flow case is a phase prediction, not a live hop.

03

Architecture

from API contracts
Input
Any skill as an argument.
Gate
Predictable by jev? Can it break into structured outcomes?
Output
Phase name for /flow-next-flow; discrete outcomes otherwise; or an explicit not-predictable report.
04

Edge cases

from R-ID errors
Missing or unreadable
Report and produce no prediction (R1).
Assessment fails
Report the failure and produce no prediction (R2).
Not predictable
Report that result; invent no structured prediction or phase (R4).
05

Boundaries

scope: business
Is
  • Assess Jev-predictability of a skill argument
  • Predict the flow-next phase for /flow-next-flow
  • Emit discrete structured outcomes when predictable
Is not
  • Does not actually run the conductor
  • Does not execute or implement the argument skill
  • Does not replace /flow-next-flow
06

Decision

flat
D1 · prediction over execution
Predict the conductor's next phase without running the hop loop.
“without actually running the conductor”
Rejected: a live /flow-next-flow run that chooses the phase by executing it.
Parked unknowns
  • Exact fields of a structured-outcomes prediction beyond the /flow-next-flow phase case.
  • How a skill argument is resolved (slash name, skill file, or pasted body).
Render lens, not record.
